# Migração para v1.0

Este guia documenta as mudanças e novos recursos da versão 1.0 do V12. A maioria das mudanças é aditiva — seu código existente continuará funcionando, mas agora você pode aproveitar funcionalidades que simplificam e fortalecem a aplicação.

## Rotas Tipadas

**O que mudou**: Quando um `schema` é fornecido na definição de rota, os tipos de `request.body`, `request.params`, `request.query` e `request.headers` são inferidos automaticamente a partir dos schemas Zod.

**Antes (v0.x)**:

```ts
router.post('/', {
  schema: createUserSchema,
  handler: ({ request, container }) =>
    container.resolve(UsersController).create(request.body as CreateUserInput),
});
```

**Agora (v1.0)**:

```ts
router.post('/', {
  schema: createUserSchema,
  handler: ({ request, container }) =>
    container.resolve(UsersController).create(request.body),
});
```

**Ação necessária**: Remova os casts manuais (`as T`) dos handlers que já possuem `schema` definido. O TypeScript irá inferir corretamente.

## EventBus Tipado com `defineEvent`

**O que mudou**: Agora é possível declarar eventos com payload tipado usando `defineEvent`. Isso garante type-safety tanto no `emit` quanto no `on`.

```ts
import { defineEvent } from '@eddiecbrl/v12';

export const UserCreated = defineEvent<{ userId: string; email: string }>('user.created');

// Emitindo (type-safe)
eventBus.emit(UserCreated, { userId: '123', email: 'a@b.com' });

// Ouvindo (payload tipado)
eventBus.on(UserCreated, (payload) => {
  console.log(payload.userId); // string
});
```

**Ação necessária**: Nenhuma — a API antiga com strings continua funcionando. Migrar para `defineEvent` é opcional mas recomendado.

## Mensagens de Erro do Container com Cadeia de Dependências

**O que mudou**: Quando uma dependência falha ao ser resolvida, o erro agora inclui a cadeia completa de resolução, facilitando o debug.

**Antes**:
```
Cannot resolve token "UsersRepository"
```

**Agora**:
```
Cannot resolve "UsersRepository"
  → required by "UsersService"
  → required by "UsersController"
```

**Ação necessária**: Nenhuma — melhoria automática nas mensagens de erro.

## Graceful Shutdown

**O que mudou**: O `createApp` agora configura automaticamente graceful shutdown. Quando o processo recebe `SIGTERM` ou `SIGINT`, o framework:

1. Para de aceitar novas conexões
2. Aguarda requisições em andamento finalizarem
3. Executa hooks `onShutdown` registrados nos módulos
4. Fecha o servidor

```ts
const app = await createApp({
  modules: [...],
  shutdown: {
    timeout: 10_000, // máximo de 10s para finalizar (padrão: 30s)
  },
});
```

**Ação necessária**: Nenhuma — ativado por padrão. Customize o `timeout` se necessário.

## DI com Request Scope

**O que mudou**: O container agora cria automaticamente um Child Container por requisição. Providers registrados com `scope: 'request'` são instanciados uma vez por requisição e descartados ao final.

```ts
defineModule({
  name: 'auth',
  providers: [
    { provide: CurrentUser, scope: 'request', useFactory: (ctx) => ctx.request.user },
  ],
});
```

**Ação necessária**: Nenhuma para código existente. Aproveite o novo scope se precisar de providers por requisição.

## EventBus com Tratamento de Erros

**O que mudou**: O EventBus agora captura erros em listeners sem derrubar a aplicação. Erros são logados automaticamente e podem ser interceptados com um handler global.

```ts
const app = await createApp({
  events: {
    onError: (event, error) => {
      logger.error({ event, error }, 'Event handler failed');
    },
  },
});
```

**Ação necessária**: Nenhuma — erros que antes causavam crash agora são capturados. Adicione `onError` se quiser tratamento customizado.

## Métricas Prometheus

**O que mudou**: O endpoint `/metrics` agora expõe métricas no formato Prometheus por padrão, incluindo:

- `http_request_duration_seconds` (histograma)
- `http_requests_total` (counter por status e rota)
- `nodejs_*` (métricas padrão do runtime)

**Ação necessária**: Nenhuma — ativado por padrão. Configure seu Prometheus para scrape em `/metrics`.

## CLI Refatorada

**O que mudou**: A CLI foi refatorada internamente para melhor manutenção e extensibilidade. Não há mudanças nos comandos disponíveis ou na interface de uso.

**Ação necessária**: Nenhuma.

## JSDoc nos Exports

**O que mudou**: Todas as funções e tipos públicos agora possuem JSDoc completo. Isso melhora a experiência no editor com autocomplete e hover documentation.

**Ação necessária**: Nenhuma — benefício automático no IDE.

## SDK Generator Melhorado

**O que mudou**: O gerador de SDK agora produz código mais limpo e tipado, com suporte a:

- Inferência de tipos de retorno a partir dos schemas
- Nomes de métodos derivados dos nomes das rotas
- Tratamento de erros tipado

```bash
npx v12 sdk --output ./sdk.ts --url http://localhost:3000
```

**Ação necessária**: Regenere o SDK caso esteja utilizando. O output mudou mas a interface pública é compatível.

## Checklist de Migração

1. ✅ Remova casts `as T` desnecessários em handlers com schema
2. ✅ Considere migrar eventos string para `defineEvent`
3. ✅ Regenere o SDK se estiver utilizando
4. ✅ Revise `shutdown.timeout` se tiver requisitos específicos
5. ✅ Configure scraping do Prometheus em `/metrics` se desejar observabilidade
